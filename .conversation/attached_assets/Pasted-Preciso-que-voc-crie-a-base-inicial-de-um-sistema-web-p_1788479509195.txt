Preciso que você crie a base inicial de um sistema web para um consultório de fisioterapia, 
como parte de um Projeto Integrador acadêmico (Desenvolvimento Web).

STACK:
- Backend: Python + Flask
- Banco de dados: SQLite para começar (Flask-SQLAlchemy como ORM)
- Frontend: HTML + CSS + JavaScript (pode usar Bootstrap para estilização)
- Autenticação: Flask-Login (ou similar) para controle de sessão

TAREFA ATUAL: Sistema de login com dois níveis de permissão

Crie a estrutura inicial do projeto com uma tela de login que suporte DOIS tipos de usuário:

1. ADMIN
   - Acesso total ao sistema
   - Pode cadastrar/editar/remover profissionais
   - Pode ver relatórios mensais e dados de todos os pacientes
   - Pode gerenciar altas do sistema

2. FISIOTERAPEUTA
   - Acesso restrito à própria agenda e aos próprios pacientes
   - Pode cadastrar pacientes e registrar atendimentos/presenças
   - Não pode gerenciar outros profissionais nem ver relatórios administrativos gerais

REQUISITOS TÉCNICOS:
- Tabela "usuarios" no banco de dados com pelo menos: id, nome, email, senha (com hash, 
  usando werkzeug.security ou bcrypt — nunca salvar senha em texto puro), tipo_usuario 
  (admin ou fisioterapeuta)
- Tela de login (HTML) com campos de email e senha
- Após login, redirecionar para uma dashboard diferente dependendo do tipo de usuário 
  (ex: /dashboard/admin ou /dashboard/fisioterapeuta)
- Proteger as rotas: usuário não pode acessar página de admin se for fisioterapeuta 
  (e vice-versa), redirecionando ou bloqueando o acesso
- Mensagem de erro clara se email/senha estiverem incorretos
- Botão de logout funcional

ACESSIBILIDADE (requisito do projeto):
- Formulário de login com labels associados aos campos (<label for="...">)
- Contraste de cores adequado
- Mensagens de erro anunciáveis por leitor de tela (aria-live)

ORGANIZAÇÃO DO CÓDIGO:
- Separe em arquivos: app.py (rotas principais), models.py (modelos do banco), 
  templates/ (HTML), static/ (CSS/JS)
- Use Blueprints do Flask se fizer sentido para organizar melhor as rotas de auth
